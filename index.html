Goal
绑核的目标不是让 CPU 更快，而是让关键路径更稳定。
核心收益 = 更少迁移 + 更少竞争 + 更少远端访问 + 更可控的中断处理
性能优化的对象是 host-side 稳定性03

Isolation

降低抢占的关键是减少竞争者

绑核不会提升线程优先级。它通过隔离 CPU 区域，减少关键线程和普通线程在同一个 CPU 上竞争时间片。

不隔离：worker / logging / monitor / runtime 混在同一批 CPU 隔离后：关键线程、后台线程、中断处理各有更清晰的位置
CPU isolation 是稳定性的基础09
Policy Design

设计绑核策略的五步

采集allowed CPUs、NUMA、topology、visible devices、threads。
建池给每个 worker/device 计算不重叠的 CPU pool。
分角色worker、runtime、IRQ、polling、memory placement。
采集 → 建池 → 分角色 → 执行 → 验证10

Containers

容器里的绑核要尊重外部边界

  • `Cpus_allowed_list` 是当前进程能使用的真实 CPU 边界。
  • cgroup/cpuset 会限制进程，即使机器物理上有更多 CPU。
  • host 线程不一定在容器 PID namespace 里可见。
  • 父进程 affinity 可能被子进程继承。
先确认边界，再谈策略12
Risk

绑核的失败模式

过度限制CPU 太少，关键线程反而互相抢。
拓扑错误绑到远端 NUMA，增加访问延迟。
误伤线程后台线程继承或被误绑，破坏 runtime 行为。
错误绑核比不绑更危险13

Benchmark

压测绑核收益，要构造 host-bound 场景

  • 固定模型、batch、输入输出长度、并发和请求率。
  • 区分冷启动、warmup、正式测量。
  • 记录 CPU affinity、NUMA、IRQ、runtime 线程状态。
  • 对比开启/关闭时要恢复持久状态。
测的是系统，不只是一个开关15

Conclusion
系统级绑核 = 拓扑理解 + CPU 隔离 + 角色分配 + 副作用控制 + 可观测验证。

最终判断 绑核不是固定线程这么简单，而是在复杂系统里为关键路径设计稳定的运行边界。
